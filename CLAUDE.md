# Stride

A running tracker used by Neil and a few friends: https://skrappyszn.github.io/Stride/
The whole app is one file, `index.html`. There's no framework and no bundler. The only
libraries are Garmin's FIT SDK and JSZip, lazy-loaded from jsDelivr. Real people's training
data runs through it, so treat changes to data handling with care.

## Files

| File | What it is |
|---|---|
| `index.html` | The app. GitHub Pages serves it straight from `main`. |
| `manifest.webmanifest`, `icons/` | Home-screen install (name, icons, colours). |
| `img/bg/<page>.webp` | The photo behind each page's header (1600 px wide, ~30–80 KB). Set per page in the CSS as `#page-<page> .band-bg`, with `background-position-y` aimed at the subject. |
| `sw.js` | Service worker: lets the installed app open offline. The page is network-first, so pushes still go live on the next open; data APIs are never cached. Bump `CACHE` if you change what it stores. |
| `.githooks/pre-commit` | Refuses commits containing personal data (only active on Neil's machine). |
| `supabase-setup.sql` | The database schema and row-level security. |

## Workflow

1. Claude Code hooks in `.claude/settings.json` pull from GitHub when a session starts
   and again before every `git push`, so you and Neil don't overwrite each other. On a
   conflict they change nothing and block the push: rebase, keep both people's work, retest.
2. Push to `main` and it's live for every user within about a minute. There's no build
   step and no review gate, so test before you push. Use a branch for anything
   half-finished.
3. To test locally, run `python3 -m http.server 8000` and open http://localhost:8000/.
   - Sign-in only works on the live site, because the emailed link redirects there.
     Test signed-out: data stays in that browser's IndexedDB.
   - To get data in: import a backup (Setup → Import backup), drop FIT files on Setup, or
     connect your own intervals.icu API key.
4. Before pushing, check every page you touched in light and dark mode and at phone width
   (~390px), with no console errors.

## How it fits together (sections of `index.html`, in order)

- **CSS tokens**: colours on `:root` with dark-mode overrides. Volt `--accent` #d4ff3a and
  Archivo condensed italic `.display` headings are the identity.
- **Night-run look** (the "Night-run look" CSS block): dark is the default (set by the
  inline script in `<head>`, before first paint). Volt is used as light: it glows on what's
  live (`--glow`). Readouts and labels use JetBrains Mono (`--mono`). Surfaces sit on a faint
  grid with grain. Motion plays only when you arrive at a page (`arrive()`), never on
  re-renders, and is off with reduced motion.
- **Layout**: a top bar with tabs (a bottom dock under 720px), and every page starts with
  `band({ eyebrow, title, sub, stats, extra })`, the full-width "poster" header, then
  `<div class="wrap">` cards. Neil chose this layout to differ from his other sites. Don't
  add a sidebar.
- **Plans**: in `PLANS`. `build` and `5k` are fixed 8-week templates gated weekly by
  `gateFor()`, which decides advance/repeat/back. `marathon` is generated by
  `marathonWeeks()` from `doc.race`, follows the calendar, and adapts via `longCap()`:
  the long run is never more than 2 mi past the longest run in the last 21 days.
  `track` has no plan. `schedule()`, `sessionFor()` and `planState()` branch on the plan.
- **FIT analysis**: `analyzeFit()` (between the `ANALYZE` markers) is pure, with no DOM.
  Garmin's run/walk splits (`rwdRun`/`rwdWalk`/`rwdStand`) beat the cadence fallback.
  Recovery HR is undocumented session field 202.
- **Storage**: IndexedDB `stride` has two stores. `doc/main` is one document per user.
  `samples/<runId>` holds the second-by-second arrays per run. `normalize()` fills
  defaults for older docs. **When you add a field, add its default there.**
- **Sync (Supabase)**: there are two tables. `stride_docs` holds one row per user, written
  compare-and-set on `version`. A stale write returns no rows, which triggers
  `reconcile()` and asks the user which copy to keep. `stride_samples` holds one
  write-once row per run, fetched lazily. Writes are debounced 2.5 s. Sync bookkeeping
  lives in `doc.sync` and is stripped by `blobOf()` before upload; save it with
  `saveLocal()`, never `save()`.
- **intervals.icu import**: `checkIntervals()` runs on open and on focus (at most every 5
  min). It pulls new runs' original FIT files, plus wellness data (weight in kg →
  stored in lbs) into `doc.body[date]`. Only the API key is synced (`doc.intervals.key`).
  What's been seen is per-device, in localStorage.
- **Crew board**: the third table, `stride_crew`, holds one opt-in row per person: display
  name, crew code, and this week's runs/minutes/miles/streak. Nothing else. RLS lets you
  read only your own crew (via `stride_my_crew()`) and write only your own row. The
  card shows "almost ready" until the SQL has been run.
- **Also in the doc**: `goals`, `shoes`/`defaultShoe` (`run.shoeId`), `pains` (body
  map; shin/Achilles or a sharp knee adds a red check-in with `stage:'map'`),
  `routines`, `crew`. Per-device niceties (dismissed cards, sound) live in
  `prefs` (localStorage).
- **Fill-ins**: `enrichRuns()` runs after sync and after imports. It adds fields that older
  runs lack: `best` (fastest mile/5K, from samples) and `tempF` (Open-Meteo hourly
  history at the start point rounded to ~1 km; no key). `undefined` means not tried yet.
- **Standards**: `standardRows()` (Body tab) and `bestsCard()` (Progress) compare against
  published norms: BMI, ACE body fat, Garmin/Cooper VO2 max, WHO activity minutes, and an
  approximate age grade. They need `profile.sex`, `birthYear` and `heightIn` (Setup → About you).
- **Routines**: `MOVES` (each a stick figure looping through poses `a`, `b`, optional `c`, or
  its own `seq`; joints in a 120×120 box). Poses are converted to bone angles and animated
  by rotation (`poseAt`, `animateFigures`), so keep each bone's length the same in every
  pose: thigh 23, shin 22, upper arm 17, forearm 15. Check new moves on a filmstrip of
  frames, not just the end poses. and `ROUTINES` (before/after a run, desk break, strength). The player
  (`RP`, `#routine/<id>`) times from the clock, keeps the screen awake and beeps on changes.
  Finishing ticks the matching Today tasks and appends to `doc.routines`.
- **The journey** (`drawJourney`): one road from the first run to the end of the plan,
  split into chapters (plan phases, or months). Runs are waypoints, milestones are
  checkpoints, and a marker shows today. It's on Today and Progress.
- **Moments** (`maybeMoment`): full-screen scenes for a new run arriving and for a
  finished week (Sunday evening, or Monday/Tuesday). Each shows once per device, tracked
  in `prefs` (`arrivalSeen`, `weekSeen`). The first time a device opens, it records where
  you are and shows nothing, so an old backlog doesn't flood in.
- **Intake** (`#intake`, `INTAKE_Q`, `intakePlan`): first-time users answer about six
  questions (goal, how long they can run now, days a week, niggles, whether they sit all
  day, about them). The answers pick the plan and `doc.startWeek`, and are stored in
  `doc.intake`. `focus()` turns them into what Stride emphasises: Today's stretches
  (`dayTasks`), the soreness options (`soreOptions`) and the routine it suggests. With no
  intake, `focus()` returns the old defaults, so existing accounts don't change until
  they take it.
- **Self-setting numbers**: `autoZones()` sets the zones from the watch's threshold in
  the FIT files, or from age until a run brings one (`profile.zonesAuto`). It never
  overrides `zonesSet`. `goalIdeas()` suggests goals from the person's own runs.
- **Coach notes** (`coachNotes`): rules over the data (gaps, heat, test-route HR trend,
  drift, too-hard runs, effort versus HR, ramp, recovery, cadence and stride, weight).
  The top three show on Today and Progress. Add a rule as one more `add(priority, tone,
  html)` call.
- **Charts**: hand-built SVG (`chartLine`, `chartColumns`, `chartDaily`, `chartTrace`)
  with hover via `_tip`. One measure per chart, never two y-axes.

## Rules

- **The repo is public.** Never commit anyone's runs, weights, emails, keys or exports.
  `SEED` stays `{}`. The Supabase *publishable* key in the file is meant to be public;
  row-level security is what protects data.
- **Database changes**: add the SQL (with RLS policies scoped to `auth.uid() = user_id`)
  to `supabase-setup.sql` in the PR. Neil runs it in the Supabase SQL editor. The app
  must keep working before the SQL is run.
- **Don't break existing docs.** Users have data in the current shape. Add fields with
  defaults, and migrate in `normalize()`; never rename or drop fields.
- Units are miles, lbs and bpm. Dates are local `YYYY-MM-DD` strings (`ymd()`,
  `addDays()`, `weekStart()` = Monday).
- Health copy is advice, not diagnosis. Keep the hard-stop rules (sharp pain, bone pain,
  red-flag check-in pauses the plan).
- **Keep it understandable for non-runners.** Any new number or chart gets a plain-English
  entry in `EXPLAIN` (or `RUN_TERMS` on the run page) behind an `infoBtn` "?". Tooltips
  are extra, not the explanation: phones don't hover.
- Match the surrounding code: terse comments that say *why*, template-string rendering,
  `data-action` click delegation in the single click handler.
